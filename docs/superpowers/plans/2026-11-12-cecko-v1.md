# Cecko v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the empty `new-macos-app` skeleton into Cecko v1: a one-window C++ editor with explorer, syntax highlighting, Run/Stop with an interactive console, inline compile errors, four themes, CS/EN UI.

**Architecture:** All logic without UI lives in `CeckoCore` (Foundation only, Swift Testing, test first): tokenizer, diagnostics parser, encoding detection, editor assists, file tree/ops, console buffer, pseudo-terminal process, toolchain (locate/compile/run), theme data, CLI launcher. The `Cecko` target is a thin SwiftUI + AppKit layer: `NSTextView` editor and console wrapped in SwiftUI, `NavigationSplitView` window, one `@Observable` `Workspace` model.

**Tech Stack:** Swift 6.4, SwiftUI + AppKit (macOS 27, Liquid Glass APIs), Swift Testing, SwiftPM, Sparkle (already wired), system `clang++` via `xcrun`.

**Spec:** `docs/superpowers/specs/2026-11-12-cecko-ide-design.md` (+ mockup `2026-11-12-cecko-mockup.html`)

## Global Constraints

- macOS 27 only (`.macOS(.v27)`, `LSMinimumSystemVersion 27.0`); no fallbacks for older systems.
- No Xcode project; SwiftPM + `build.sh`. Core has no SwiftUI/AppKit imports.
- No new package dependencies (Sparkle only).
- UI strings: English source strings as keys, Czech in `Resources/cs.lproj/Localizable.strings`; follows the macOS language. Theme flavour texts stay English.
- Compiler messages are shown in their original English.
- Glass is the default theme; theme choice persisted.
- Every user-visible change gets a line under `## Unreleased` in `CHANGELOG.md`; manual (EN + CS) describes every control.
- Conventional Commits with scope (`feat(core): …`, `feat(ui): …`); no AI attribution trailers; no push.

## Review Focus

1. A program that prints a prompt without `\n` (`cout << "a: "; cin >> x;`, also `printf`/`scanf`) — the prompt must be visible before input is requested → Task 7 test `promptWithoutNewlineArrivesBeforeInput`.
2. An infinite output loop (`while(1) cout << "x";`) — the UI must stay responsive and Stop must kill it → Task 6 test `bufferIsCappedAtLimit` + Task 7 test `terminateKillsRunningProcess`.
3. A file from Code::Blocks in Windows-1250 with Czech diacritics — opens readable and saves back byte-identical when unchanged → Task 1 test `windows1250RoundTrip`.
4. Errors reported in a header or with `note:` lines, or a linker error with no line (`undefined reference to main`) — must not crash or mis-highlight; linker error appears in the console only → Task 3 tests `linkerErrorHasNoLocation`, `notesAreAttachedNotCounted`.
5. Paths with spaces and Czech characters (`~/Škola/úkol 1.cpp`) — compile and run must work → Task 8 test `compilesFileInPathWithSpacesAndDiacritics`.

### Task 7: Pseudo-terminal process

**Files:** `Sources/CeckoCore/PTYProcess.swift`; Test `PTYProcessTests.swift`.

**Produces:**
```swift
public enum Termination: Equatable, Sendable { case exited(Int32), signaled(Int32) }
public final class PTYProcess: @unchecked Sendable {
    public init(executable: URL, arguments: [String] = [], currentDirectory: URL)
    public func start(onOutput: @escaping @Sendable (String) -> Void,
                      onExit: @escaping @Sendable (Termination) -> Void) throws
    public func send(_ text: String)        // write to the pty master
    public func sendEOF()                   // ^D
    public func terminate()                 // SIGTERM to the process group, SIGKILL after 0.5 s
    public var isRunning: Bool { get }
}
```
Approach: `openpty`, disable `ECHO` and `OPOST` on the slave termios (the UI shows input itself; `\n` stays `\n`), `posix_spawn` with `POSIX_SPAWN_SETSID` and file actions dup2-ing the slave to 0/1/2, read master on a background `DispatchSourceRead`, decode UTF-8 incrementally (keep incomplete trailing bytes), `waitpid` on a background thread, deliver `onExit` after the output is drained.
- [ ] Tests (use `/bin/sh -c …`): `capturesOutput` (`echo ahoj` → "ahoj\n", `.exited(0)`); `promptWithoutNewlineArrivesBeforeInput` (`printf 'a: '; read x; echo "got $x"` → output contains "a: " before `send("5\n")`, then "got 5"); `stdoutIsATerminal` (`[ -t 1 ] && echo tty`); `exitCodeIsReported` (`exit 3`); `terminateKillsRunningProcess` (`while :; do :; done`, terminate → `.signaled`) within 2 s; `utf8SplitAcrossReadsIsDecoded`.
- [ ] Fail → implement → pass → commit `feat(core): run programs in a pseudo-terminal`.

### Task 8: Toolchain — compiler check, compile, run outcome, compat header

**Files:** `Sources/CeckoCore/Toolchain.swift`, `Sources/CeckoCore/CompatHeaders.swift`, `Sources/CeckoCore/RunOutcome.swift`; Tests `ToolchainTests.swift` (integration tests with the real clang, skipped via `.enabled(if:)` when no compiler).

**Produces:**
```swift
public enum CompilerStatus: Equatable, Sendable { case available(version: String), missing }
public struct Toolchain: Sendable {
    public static func detect() -> CompilerStatus   // `xcode-select -p` must succeed and `xcrun --find clang++` must resolve; never runs /usr/bin/clang++ (that shim pops Apple's install dialog)
    public static func installCommandLineTools()    // runs `xcode-select --install`
    public init(supportDirectory: URL)              // writes compat headers to <dir>/include once
    public func compileArguments(sources: [URL], output: URL) -> [String]
        // ["clang++", "-std=gnu++20", "-Wall", "-g", "-fno-color-diagnostics", "-isystem", "<dir>/include", <sources…>, "-o", <output>]  (run via /usr/bin/xcrun)
    public func compile(sources: [URL], output: URL) async -> CompileResult
}
public struct CompileResult: Sendable { public let succeeded: Bool; public let diagnostics: [Diagnostic]; public let rawOutput: String }
public enum CompatHeaders { public static let bitsStdcpp: String }  // includes the standard C++20 headers available in libc++
public enum RunOutcome: Equatable, Sendable { case finished, failed(code: Int32), crashed(signalName: String), stopped
    public init(_ t: Termination, stoppedByUser: Bool) }  // SIGSEGV → "segmentation fault", SIGABRT → "abort", SIGFPE → "division by zero", SIGBUS → "bus error", else "signal N"
```
`compile(sources:)` takes a list so a future "folder = one program" mode is an addition (spec §6). Output binary goes into a per-run temporary directory, never the student's folder.
- [ ] Tests: `argumentsContainShimAndStandard`; `compatHeaderWritten` (file `<dir>/include/bits/stdc++.h` exists); `compilesHelloWorld` (real clang, run the result with `PTYProcess` → "Hello"); `compileErrorProducesDiagnostic` (missing `;` → `succeeded == false`, one `.error` at line 3); `bitsStdcppCompiles` (`#include <bits/stdc++.h>` program compiles); `compilesFileInPathWithSpacesAndDiacritics` (`Škola/úkol 1.cpp`); `runOutcomeMapsSignals` (SIGSEGV → `.crashed("segmentation fault")`, user stop → `.stopped`).
- [ ] Fail → implement → pass → commit `feat(core): locate clang, compile and map run outcomes`.
